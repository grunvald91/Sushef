## Rich Markdown для обычных ответов (10.10.2026)

Теперь не только JSON-рецепты, но и обычные ответы ClaudeHub (вопросы о рыбе, спасение блюд, технология, вопросы о шагах) направляются в native `sendRichMessage(markdown=...)`. Автоматическая структуризация исправляет склеенные пункты, добавляет читаемые секции, не меняя рецептурные числа, и защищает от произвольного HTML. При подтверждённом TelegramBadRequest предусмотрен запасной режим форматированного Telegram HTML.

Если свободный ответ содержит ингредиенты и минимум два шага, появляется кнопка **«🧾 В карточку и готовить»**. По отдельному нажатию она превращает актуальный ответ в структурированный JSON-рецепт с технологическими пояснениями и существующими таймерами; расходует одну AI-квоту и не принимает устаревшие кнопки от прошлой беседы. # 👨‍🍳 Сушеф — Telegram, расширяемый кулинарный агент

Личный су-шеф на русском языке: уважительный, добрый, остроумный ИИ-помощник для готовки, исправления блюд и планирования меню.

> **Статус:** исходники v0.2 в разработке. Подключение Telegram и ClaudeHub не проверено живым запуском. Фото реализовано как экспериментальный API-маршрут, **выключенный** по умолчанию; голос и Mini App ещё не реализованы.

## Персональное знакомство и стиль (ветка feat/personalized-conversation-20261009)

- Первое знакомство с возможностью пропуска, выбор имени и формы «ты»/«вы»;
- четыре стиля общения с примерами на одной кулинарной ситуации, возможность их сочетать;
- долговременное сохранение выбранного общения в профиле, смена через «💬 Стиль общения»;
- расширенная подтверждаемая память о кулинарных открытиях и истории блюд;
- более живые и профессионально адаптивные подсказки без навязчивых повседневных предупреждений.

Подробности: [docs/PERSONALIZATION.md](docs/PERSONALIZATION.md).
Здесь описан код ветки, а не подтверждение развёртывания на сервере.

## Реализовано в исходном коде v0.2

- Telegram-меню с inline-кнопками и обычным текстовым чатом;
- подбор **структурированного рецепта** из продуктов (название, ингредиенты, время, порции, шаги, примечания о безопасности);
- «Спасти блюдо», вопросы шефу и **структурированное недельное меню** (7 дней × 3 приёма пищи), сохраняемое для дальнейшего просмотра;
- пошаговый режим готовки с сохранением текущего шага;
- **автоархив всех создаваемых рецептов**, отдельное избранное и недостающие покупки из записанных запасов;
- расширенный профиль: аллергены, исключения, вкусы, кухни, острота, текстуры, бюджет, время, уровень, техника и порции;
- хранение до 40 сообщений между режимами; отдельный /reset для очистки диалога, без удаления рецептов;
- добровольные, **явно подтверждённые** долговременные заметки (/remember и /memory), статистика повторяющихся отзывов;
- лимит обращений к ClaudeHub в сутки на пользователя;
- SQLite для разработки, PostgreSQL для Docker-продакшна; **миграции Alembic**, безопасный скрипт резервного копирования и /export_my_data;
- учёт продуктов дома (г, кг, мл, л, шт) с безопасным сопоставлением единиц;
- по меню можно выбрать завтрак, обед или ужин и получить подробный рецепт;
- перемещение назад в процессе готовки;
- оценки приготовленного блюда: великолепно, вкусно, пересолено, суховато, остро или не понравилось; последние оценки учитываются в будущих AI-подсказках;
- экспериментальная отправка фото в модель по Anthropic Messages (только с `VISION_ENABLED=true` после проверки).

**Ограничения:** автоматическая обработка фото через ClaudeHub **не подтверждена** и отключена по умолчанию. Голосовые сообщения, автоматическая синхронизация реального холодильника, пуш-таймеры, Mini App, платежи и проверенная база нутриентов пока отсутствуют. Список недостающих покупок сравнивает **точные названия продуктов** и совместимые количества; единицы без надёжного пересчёта требуют ручной проверки.

## Запуск без Docker (Python 3.11+)

1. Создайте Telegram-бота через [@BotFather](https://t.me/BotFather), сохраните токен.
2. Создайте API-ключ ClaudeHub в своём личном кабинете.
3. Скопируйте конфигурацию: `cp .env.example .env`.
4. Впишите **только в локальный .env** значения `TELEGRAM_BOT_TOKEN` и `CLAUDEHUB_API_KEY`.
5. При необходимости смените `CLAUDEHUB_MODEL` на реальный доступный идентификатор модели в ClaudeHub.
6. Установите зависимости и запустите:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
export DATABASE_URL=sqlite+aiosqlite:///./sushef.db
PYTHONPATH=src alembic upgrade head
PYTHONPATH=src python -m sushef
```

Для Windows: `.venv\Scripts\activate`, а переменную PYTHONPATH можно задать `$env:PYTHONPATH = 'src'` в PowerShell.

**Внимание:** токены не отправляйте в чат и не коммитьте. `.env` исключён через `.gitignore`.

## Запуск в Docker с PostgreSQL

1. Заполните `.env` по примеру.
2. Запустите `docker compose up -d --build`.
3. Посмотрите `docker compose logs -f bot`.

В compose используются собственная БД PostgreSQL и один экземпляр polling. Не запускайте одновременно второй бот с тем же токеном и polling.

Эти тесты не требуют реальных ключей и не обращаются к ClaudeHub. Отдельная ручная проверка: /start → «Мои продукты» → «Добавить» → «Что приготовить?» → рецепт → «Покупки» → «Готовим пошагово» → назад/вперёд → «Меню на неделю» → выбор конкретного блюда → /profile → /reset → /delete_me.

## Первый запуск без GitHub Actions

Если ключи занесены в **GitHub Settings → Secrets and variables → Actions**, они не появляются автоматически на сервере. Их значения доступны только заданию Actions, которое явно использует секрет. Чтобы не тратить минуты Actions, запустите бота на сервере с защищённым локальным файлом `.env`, **не коммитьте его в Git**. Подробности в [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).

Для начальной установки без PostgreSQL используйте `docker compose -f compose.sqlite.yaml up -d --build`. Это один контейнер и постоянный том SQLite. Для штатного запуска PostgreSQL по-прежнему доступен через `compose.yaml`.

## Что важно в расширенной версии

- В `Мои продукты` можно написать по одному продукту на строку, например `рис 700 г`, `молоко 1 л`, `яйца 6 шт`. Команды «Добавить» и «Убрать» меняют записанный остаток, а не настоящий холодильник.
- `Покупки` считает недостаток только по совпадающим названиям и измерениям (кг→г, л→мл). Иные случаи помечает для проверки; нет попытки угадывать эквивалентность продуктов.
- `Меню на неделю` требует ответа модели в валидном JSON для всех 21 блюд. Сохранение плана и просмотр по дням работают на уровне кода. При смене аллергенов/исключений старый план сбрасывается.
- Если изменить аллергенные ограничения, старый рецепт и активная готовка сбрасываются. Избранные старые рецепты доступны только для ознакомления, без автоматического запуска приготовления с новыми ограничениями.
- `VISION_ENABLED=false` до подтверждения поддержки image-content через ClaudeHub. Экспериментальный фотообработчик ограничивает размер и объём обращений. Фото не сохраняются в БД, продукты автоматически не добавляются.
- Старые таблицы v0.1 сохраняются; новые таблицы `pantry_items` и `weekly_plans` создаются при запуске. До публичного релиза нужны Alembic, резервное копирование и тесты на отдельном стенде.

## Обратная связь после готовки

После рецепта или последнего шага нажмите «Оценить результат». Сушеф хранит не более 50 последних оценок пользователя в отдельной таблице и передаёт 10 последних оценок ClaudeHub для персонализации. Оценка означает субъективное впечатление, **не** объективную проверку качества и безопасности. `/delete_me` удаляет и эту историю.

## Научно-кулинарная лаборатория — ветка `feat/fermentation-lab`

- **Микробиология:** полезные пищевые культуры, молочнокислая ферментация, закваски, кодзи.
- **Холодные и тёплые режимы:** пояснение различий, подбор только под конкретный продукт и проверенный протокол.
- **Внешние ферменты:** пищевые амилазы, протеазы, липазы и другие препараты; различие ферментативного гидролиза и микробного брожения.
- **Журнал партий:** название, указанная пользователем технология/источник, температура (°C), pH, заметки, история наблюдений, завершение/удаление.
- **Безопасность:** консервативный протокольный скрининг никогда не утверждает, что продукт безопасен; правила исключают «сертификацию» по запаху, одной цифре pH или температуре.

Раздел открывается кнопкой «🔬 Микробиология и ферментация» или командой `/ferment`.

**Ограничение:** интеллектуальные рекомендации и журнал не являются анализатором пищевой безопасности. Функция опирается на научные и пищевые источники, но запросы к ClaudeHub и новые Telegram-сценарии не проверялись в работе. Подробнее — [docs/FERMENTATION.md](docs/FERMENTATION.md).


## 📚 Библиотека технологических протоколов (новая ветка)

В разделе `/ferment` теперь есть кнопка «Каталог протоколов». На старте — документированные профильными учреждениями рецептуры **квашеной капусты, ферментированных огурцов и йогурта**. Для каждого протокола сохраняются ID, версия карточки, официальный первоисточник, сырьё, исходные меры, этапы, параметры контроля и основания для остановки/пересмотра.

Можно задавать вопросы по выбранному протоколу и создавать журнал, привязанный к его версии. В журнале доступна **предупредительная проверка** последнего замера по параметрам этапа; она не подтверждает безопасность партии.

Пока нет готовой документированной карточки для кодзи, натто, универсального «холодного/горячего» способа или конкретных внешних ферментов — эти направления требуют проверенной документации на культуру/препарат и технологию. Подробнее: [Библиотека протоколов](docs/PROTOCOL_LIBRARY.md).


## Научная библиотека: кодзи, культуры и внешние ферменты

В `/ferment` добавлена кнопка «🧬 Наука: кодзи, ферменты и культуры». Эта библиотека **отделяет научные/производственные справки от пригодных для ведения журнала протоколов**.

- **Новый документированный метод:** закваска King Arthur Baking: 113 г исходной муки + 113 г воды; с 3-го дня — подкормки 113:113:113, готовность определяется устойчивым удвоением объёма после кормления, а не датой.
- **Кодзи:** справка по научному обзору Allwood et al. с указанием рисков `Bacillus cereus`. Условия промышленного кодзи нельзя автоматически повторять дома.
- **Препараты ферментов:** Scottzyme PEC5L (жидкая пектиназа), Rapidase Clear Extreme (гранулы); точно зафиксированы производитель, форма, область применения и дозировки **только для винодельческого сырья**. Не универсальные кухонные нормы.
- **Культуры:** различие технологических заквасок, ферментированной еды и пробиотиков по материалам ISAPP.

Инструкции по источникам и ограничениям: [docs/KOJI_ENZYMES_STARTERS.md](docs/KOJI_ENZYMES_STARTERS.md). Для научных справочных карточек нельзя создать «подтверждённую безопасную домашнюю партию» — нет такого уровня доказанности. Код требует локальных тестов и проверки ClaudeHub перед включением в рабочий бот.

- **Дополнительно:** справка по Novonesis Amylase AG 300 L — коммерческой амилазе для осветления соков, с заявленной производителем активностью 300 AGU/мл и данными только для соответствующего пищевого применения.


## ⏱ Пошаговое приготовление и устойчивые таймеры

- В JSON рецепта возможно поле `step_timers` с рекомендуемым временем для отдельного шага. Неверные подсказки игнорируются, а не включаются автоматически.
- «👨‍🍳 Готовим пошагово» → «⏱ Поставить таймер»: рекомендованная длительность, 1/5/10/15/30 минут или своё число 1–240; до 5 параллельных отсчётов на человека.
- **Отсчёт запускает только пользователь**, шаг не перелистывается при срабатывании. Рецепт сохраняет последний шаг при повторном входе. `/timers` показывает и позволяет отменять действующие таймеры.
- Таймеры хранятся в PostgreSQL/SQLite, переживают перезапуск и проверяются отдельным циклом aiogram каждые ~5 секунд. Если сервер недоступен, уведомление будет **запоздалым** после запуска; оно не может прийти с выключенного бота. После ошибок Telegram предусмотрены ограниченные повторные попытки.
- Таймер не подтверждает безопасность пищи: проверяйте реальную температуру/готовность. Ферментационные протоколы не заменяются LLM-таймерами.
- Миграция `0002_timers` запускается Alembic перед ботом. Без неё запуск останавливается с ошибкой, чтобы не повредить данные. **Сделайте бэкап** перед обновлением живой базы.

Документация: [docs/COOKING_TIMERS.md](docs/COOKING_TIMERS.md). Тесты: `tests/test_timers.py`, `tests/test_timer_storage.py`, `tests/test_migrations.py`. Минуты GitHub Actions не используются.


## 🚀 Выкладка через GitHub Codespaces (без GitHub Actions)

Для первого запуска на сервере `155.212.162.47` используется ветка `feat/guided-cooking-timers`: откройте **Codespace репозитория Sushef**, разрешите ему закрытые секреты `SERVER_SSH_KEY`, `TELEGRAM_BOT_TOKEN`, `CLAUDEHUB_API_KEY`. В редакторе выберите **Terminal → Run Task → «Сушеф: Тесты + деплой на сервер 155»**. Это одна явно запускаемая задача, не автодеплой при открытии Codespace.

Задача прогоняет полный pytest, затем осторожно разворачивает только Docker-проект `sushef` в `/opt/sushef` по SSH. Существующая PostgreSQL-база перед миграцией сохраняется в резервную копию; на чистом сервере используется отдельный том. После запуска выполняется Telegram `getMe` и один короткий запрос к ClaudeHub (незначительный расход API-токенов), затем необходимо руками проверить `/start` и минутный таймер.

**Пока Codespace не запущен с этой задачей, деплой не выполнен.** Полная инструкция: [docs/CODESPACES_DEPLOY.md](docs/CODESPACES_DEPLOY.md).
