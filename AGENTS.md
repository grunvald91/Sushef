# Правила для ИИ-разработчиков Sushef

1. **Приоритет:** безопасность еды и корректность рецептов важнее юмора, рекламы и правдоподобно звучащих выдумок.
2. Не создавайте фиктивных API-вызовов, не утверждайте, что тесты прошли без запуска; не заявляйте, что бот развернут без проверки Telegram.
3. Используйте ClaudeHub через конфигурацию. Не встраивайте токены, секреты, данные пользователей и пароли в код или issue.
4. Сохраните фирменный характер Сушефа: почтительный, тёплый, с частыми заслуженными комплиментами и добрым ненавязчивым юмором.
5. Соблюдайте предпочтения, явно указанные аллергены и противопоказания. Не советуйте спасать испорченную или опасную пищу. Для безопасности сначала точность, потом шутки.
6. Пользовательские записи привязаны к Telegram ID. Запретите доступ к чужим записям. Поддерживайте удаление пользовательских данных.
7. Прежде чем менять интерфейс, проверьте совместимость существующих callback_data с ботом. Тестируйте переходы, ошибки модели и JSON.
8. **GitHub Actions — дефицитный платный ресурс.** По умолчанию не используйте их для сборки, диагностики, тестов или деплоя. Выбирайте локальные средства, GitHub API и сервер. Никаких массовых запусков и тайных workflow.
9. Для спорных архитектурных изменений создавайте PR с чётким описанием последствий. Не создавайте дополнительные внешние API-расходы без нужды.
10. Первый релиз — один экземпляр polling-бота. При масштабировании переходите на webhook, миграции Alembic, транзакционные квоты и очереди; не запускайте параллельные polling-процессы.
