# Деплой через GitHub Actions (кнопкой)

Репозиторий публичный, поэтому минуты Actions безлимитные. Workflow **Deploy** запускается только вручную:
GitHub → вкладка **Actions** → **Deploy** → **Run workflow** → выбрать ветку (обычно `main`) → **Run workflow**.
Ни push, ни pull request его не запускают.

## Секреты (Settings → Secrets and variables → Actions → Repository secrets)

| Секрет | Что это |
|---|---|
| `SERVER_SSH_KEY` | закрытый SSH-ключ для входа на сервер (целиком, со строками BEGIN/END) |
| `SUSHEF_SERVER_HOST` | адрес сервера |
| `TELEGRAM_BOT_TOKEN` | токен бота Сушефа |
| `CLAUDEHUB_API` | ключ ClaudeHub |
| `SERVER_HOST_KEY` | *необязательно:* строка known_hosts сервера. Закрепляет отпечаток сервера; без неё на каждом запуске доверяется первому увиденному ключу |

Секреты нельзя прочитать после сохранения — их видит только запущенный workflow. Не публикуйте значения в Issues, PR и чатах.

## Что делает запуск

Тот же сценарий, что в Codespaces (`scripts/deploy_via_codespaces.sh`): тесты → контрольный бэкап и восстановление БД → выкладка в изолированный проект `sushef` → smoke Telegram и ClaudeHub (один короткий запрос). Успех — только если в логе есть `DEPLOYED_OK`, `Telegram Bot API: OK` и `ClaudeHub LLM API: OK`. После этого вручную проверить в Telegram: `/start`, рецепт, `/timers`.

Поле **set_model** (необязательное) меняет `CLAUDEHUB_MODEL` в серверном `.env`, например на `claude-haiku-5-5`; копия прежнего файла остаётся рядом. Без него серверный `.env` не трогается.

## Правила безопасности публичного репозитория

- Ничего приватного в репозитории: ключи, токены, пароли, адрес сервера.
- Не добавлять триггеры `push`, `pull_request`, `pull_request_target`, `schedule`: чужой код не должен получать секреты.
- Предлагаемые чужие изменения (PR из форков) секретов не получают; всё равно смотрите их глазами перед слиянием.

## Вариант Б: запуск из другого репозитория по паролю (BookingBot)

Если SSH-ключ для Сушефа создать нельзя, а в другом репозитории уже есть секрет с паролем сервера (в BookingBot — `SERVER_SSH_PASSWORD`), деплой можно запустить оттуда: в том репозитории лежит ручной workflow «Sushef deploy (manual)». Он забирает код из этого (публичного) репозитория и запускает тот же `scripts/deploy_via_codespaces.sh`; пароль передаётся скрипту через переменную `SSHPASS` и нигде не печатается. Токены Telegram и ClaudeHub в этом варианте нужны только при самой первой установке; если серверный `.env` уже есть, он не меняется.

Недостаток: пароль root вместо ключа. Когда появится возможность, лучше перейти на ключ и отключить вход по паролю.
