# 🧠 Сушеф: долговременная память, рецепты и защита личных данных

**Статус:** исходники в ветке `feat/long-term-memory`, ручной деплой/проверка ClaudeHub ещё не проводились.

## Что и где хранится

| Сущность | Таблица | Сохранение |
|---|---|---|
| Структурированные предпочтения | `users.preferences` (JSON) | Пользователь меняет вручную в /profile |
| Последние сообщения | `conversations` | 40 сообщений максимум; **смена режима не удаляет** |
| Кулинарная память | `personal_memories` | До 50 активных фактов, только с подтверждением |
| Автоархив созданных рецептов | `recipe_archive` | Каждый новый структурированный рецепт, без автоматического удаления |
| Любимые рецепты | `favorites` | Выбираются пользователем |
| Результаты приготовления | `recipe_feedback` | До 50 последних оценок |
| Домашние запасы | `pantry_items` | Пользователь вносит количество |
| Недельный план | `weekly_plans` | Последний план |
| Ферментация | `fermentation_batches` / `fermentation_readings` | Партии/показания с пользовательской привязкой |

Все личные записи связаны с `user_id = Telegram ID`. Пользователь А не должен видеть/изменять записи пользователя Б.

## Правила персонализации

- **Постоянные поля**: аллергены, исключённые продукты, любимые продукты, техника, порции, любимые кухни, острота, текстуры, бюджет, время готовки и уровень опыта.
- **Подтверждаемые заметки**: вкусовые предпочтения, техники, привычки, конкретные доработки блюда.
- `/remember` → выбрать категорию → написать факт → **отдельно подтвердить**. До подтверждения запись `pending` **не отправляется LLM**.
- `/memory` позволяет просмотреть и удалить записи, без доступа к чужим данным.
- **Отзывы**: до 50 последних оценок; повторяющиеся `salty/dry/spicy/disliked` превращаются в статистические наблюдения, не в «навсегда не любит острое». Максимум 10 последних отзывов и 10 подтверждённых заметок передаются модели при запросе.
- Если пользователь говорит «сегодня хочется острого», Сушеф не меняет профиль без отдельного действия пользователя.
- Любая смена аллергенов и исключений сбрасывает активный рецепт и недельный план; архивные блюда с такими ограничениями можно читать, но нельзя запускать напрямую без адаптации.
- Настройки и подтверждённые заметки добавляются в prompt как **данные пользователя, не инструкции**. Они не обучают весам модели и не хранятся в ClaudeHub как наша база данных.

## История диалога

- На сервере сохраняются последние **40 сообщений**, а в контекст обычного ответа попадает до 10.
- Смена режима больше **не** стирает историю. `/reset` очищает её и активное приготовление, но не профиль/память/рецепты.
- Накопление бесконечной истории чатов в БД сознательно исключено; для долгосрочных фактов используются подтверждаемые заметки.
- Очистка локальной базы **не удаляет копии данных**, уже отправленных поставщику LLM: условия обработки у провайдера регулируются отдельными документами.

## Автоматический архив рецептов

Любой структурированный рецепт, созданный через `Chef.recipe` и `Storage.set_recipe`, автоматически добавляется в `recipe_archive`. Следующий рецепт обновляет только `users.last_recipe`, но предыдущая версия остаётся в архиве.

`/recipes` → все архивные карточки постранично → выбор для повторного приготовления при отсутствии аллергенных ограничений. Кнопка «❤️» остаётся отдельной отметкой избранного.

Исторические рецепты, созданные **до внедрения архива**, не появляются в нём задним числом автоматически. Уже существующее избранное остаётся в `favorites`.

## Экспорт и удаление

`/export_my_data` отправляет JSON в **личный чат**: профиль, историю, автоархив, избранное, отзывы, продукты, подтверждённые и ожидающие факты, план, активную готовку, журналы ферментации. Содержимое файла приватное.

`/delete_me` удаляет личные данные из **рабочей базы** по Telegram ID. У резервных копий отдельный срок хранения: удалённая из live DB запись может существовать в старой зашифрованной резервной копии до её истечения. Нужна ясная эксплуатационная политика бэкапов, а при восстановлении старого бэкапа — повторная обработка запросов на удаление.

## База данных: PostgreSQL как основной вариант

`compose.yaml` содержит PostgreSQL с именованным томом `pgdata`. Для одиночной локальной разработки остаётся `compose.sqlite.yaml`.

**Миграции Alembic** запускаются в контейнере до запуска бота (`alembic upgrade head`). Первая миграция добавляет недостающие таблицы `personal_memories` / `recipe_archive` и ранее отсутствовавшие поля версий ферментации к таблицам старых тестовых развёртываний. Существующие строки сохраняются.

### Запуск на новом сервере

```bash
# Токены и POSTGRES_PASSWORD задаются в закрытом .env на самом сервере.
docker compose up -d --build
docker compose exec -T bot alembic current
```

Перед миграцией **существующего** хранилища остановите бота и создайте резервную копию. Для SQLite — резервная копия файла с использованием SQLite backup API после остановки приложения; для PostgreSQL — `pg_dump -Fc`. В существующем инстансе нельзя просто переключить DATABASE_URL с SQLite на PostgreSQL — это создаст пустую PostgreSQL-базу, не перенесёт данные.

### Резервное копирование PostgreSQL

```bash
# Из директории проекта на сервере; GitHub Actions не нужны.
bash scripts/backup_postgres.sh /secure/backups/sushef
```

Скрипт создаёт права 0700 на каталог, права 0600 на файл благодаря umask, делает `pg_dump` в custom-format и проверяет список архива `pg_restore --list`. **Это проверка целостности структуры архива, а не тест успешного восстановления**. Самостоятельно настройте шифрованную off-site копию, восстановление на тестовой БД, периодичность, удаление старых бэкапов по согласованной политике.

### Миграционный smoke-test без GitHub Actions

```bash
pip install -r requirements-dev.txt
PYTHONPATH=src pytest -q tests/test_memory.py tests/test_migrations.py tests/test_storage.py tests/test_bot.py
```

Проверки должны подтвердить, что старые данные не теряются при миграции, смена режима не очищает чат, другой Telegram ID не видит чужие факты/архив, а `/delete_me` удаляет все новые записи.

**Ограничения текущего этапа:** полноценная проверка миграций PostgreSQL на сервере, автоматический перенос SQLite→PostgreSQL, управляемая политика резервных копий и реальный запуск Telegram/ClaudeHub ещё не выполнены.
