# Сушеф — архитектура и дорожная карта

## MVP (v0.1)

Telegram (aiogram) → обработчик → Storage (SQLAlchemy async / PostgreSQL или SQLite) → Chef (Anthropic SDK → ClaudeHub).

Все данные принадлежат конкретному Telegram ID. Текущий режим хранится в Users, история ограничена последними 40 репликами; последнее сгенерированное блюдо и избранное хранятся отдельно. Шаги приготовления сохраняются между сообщениями.

ClaudeHub получает историю беседы и настройки пользователя. Проверьте политику хранения данных провайдера до публичного запуска. Результат модели — рекомендация, а не измерение или подтверждение безопасности пищи.

### Подтверждённые ограничения

- Текстовые диалоги и кнопки; **нет** живой обработки фото или голоса.
- Список покупок — полный список продуктов последнего рецепта, **не** вычисленный дефицит запасов.
- Содержание рецептов генерируется LLM; структурная проверка JSON **не гарантирует** кулинарную правильность и безопасность.
- Режим меню на 7 дней реализован как AI-консультация, без календаря и экспорта.
- Quota в базе защищает от обычного перерасхода, но конкурентный атомарный лимитер ещё требуется перед масштабированием.
- Автоматическое создание таблиц допустимо для MVP. Миграции схемы потребуются до обновления реальных пользователей.

## Следующие итерации

1. Раздельные слои bot/API/service и Alembic; корректное выделение транзакций; observability, healthcheck, резервные копии.
2. Кулинарная база знаний с лицензированными материалами, проверенными термометрическими таблицами и тестами на аллергенные ограничения.
3. Состояние холодильника / запасов, подтверждение распознавания продуктов, остатки, реальные недостающие покупки.
4. Фото через поддерживаемую vision-модель, голос через ASR; сначала тесты возможностей и цены маршрутов ClaudeHub.
5. Таймеры и напоминания: очередь фоновых задач; часовой пояс пользователя.
6. Mini App поверх одного backend: книга рецептов, календарь, карточки блюд.
7. Многоарендность и горизонтальное масштабирование: webhook + очередь, Redis, идемпотентность updates, rate-limit на уровне хранилища, метрики затрат.

## Privacy и безопасность

- Только личные чаты Telegram, без пересылки личного профиля в групповые чаты.
- /privacy — объяснение состава данных; /reset — очистка текущего диалога; /delete_me — удаление всех записей в БД.
- Ключи из окружения. Не писать содержимое диалогов и ключи в системные логи.
- Не использовать CI GitHub Actions без необходимости: локальные тесты, ручная проверка, деплой с сервера.


## Расширение 0.2

- `pantry.py` — распознавание количеств с `Decimal`, строгая конвертация г/кг, мл/л и шт, консервативное сравнение закупок.
- `weekly.py` — JSON-схема меню на 7 дней × 3 блюда и проверка структуры.
- `PantryItem` и `WeeklyPlan` — изолированные по `user_id` таблицы.
- Telegram: отдельные кнопки запасов и меню, экран дня и выбор рецепта блюда, обратный шаг готовки.
- Опциональная vision-ветка работает через формат Anthropic Messages API, но совместимость с конкретной моделью ClaudeHub **не проверена**. Отключена по умолчанию.
- Важно: данные запасов — ручная декларация пользователя, не подтверждение свежести или точных объёмов. При изменении аллергий старый рецепт и недельное меню деактивируются.

### Дальнейшие задачи до публичного релиза

Нужно провести локальные unit/integration тесты, реальный smoke-test ClaudeHub, ограничения расходов на уровне транзакций, миграции Alembic и резервное копирование. Дополнительно следует внедрить проверку аллергенов по структурированному справочнику и базу проверенных пищевых требований, а не только промпт LLM.
