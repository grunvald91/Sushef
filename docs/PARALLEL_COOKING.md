# Параллельная готовка: логика шагов и таймеров

## Проблема, которую устраняем

Нельзя предлагать выдержать горбушу 15 минут, затем заниматься
подготовкой овощей, а потом ещё 20 минут запекать овощи:
реальная выдержка рыбы получится значительно длиннее объявленной.

## Правила генерации рецепта

1. Перед выдачей шагов спланировать зависимости, активную подготовку и
   пассивные ожидания. Подготовка продуктов, которые могут ждать, ставится
   до запуска критичных коротких выдержек.
2. Совмещать ожидания там, где это технологически допустимо;
   не предполагать, что пользователь зафиксированное время подготовки
   (например, 5 минут) гарантированно уложит в срок.
3. Таймер запускается **только по нажатию**, а его завершение — повод
   проверить этап, но не автоматический переход и не гарантия готовности.
4. Если шаг можно делать во время ранее запущенного процесса, модель может
   выдать `step_overlaps`; данные показываются в полном рецепте
   и в режиме «Готовим пошагово».
5. Последующие шаги должны явно зависеть от завершения соответствующих
   процессов. При единственной духовке нельзя планировать одновременные
   стадии с несовместимыми температурами.
6. `time_minutes` означает календарную длительность приготовления,
   включая активные и пассивные этапы с реальными пересечениями.

## Пример с горбушей (логика, не универсальный терморежим)

- Подготовить овощи и рыбу **до** запекания; приправленную сырую рыбу
  держать в холодильнике.
- Поставить овощи в духовку: таймер на 20 минут. Пока они готовятся,
  рыба может выдерживаться в холодильнике не менее 15 минут (только если
  такая выдержка нужна выбранному рецепту).
- По завершении стадии овощей и выдержки рыбы добавить рыбу и довести
  блюдо до готовности. Не объявлять рыбу безопасной только по истечении
  15–18 минут; учитывать толщину и внутреннюю температуру.

Если приготовление рыбы слишком долгое, оно должно выполняться заранее,
а не искусственно «сжиматься» до окна в 5 минут.

## Новый необязательный атрибут

```json
{
  "step_overlaps": [
    {
      "step_index": 2,
      "while_step_index": 1,
      "label": "Подготовьте соус, пока овощи запекаются"
    }
  ]
}
```

`while_step_index` должен ссылаться на строго предыдущий шаг,
в `step_timers` для которого есть рекомендация таймера.
Допустима только одна подсказка на один текущий шаг.
Некорректная разметка отбрасывается без потери рецепта;
старые рецепты без `step_overlaps` продолжают работать.

## Границы реализации

Эта версия **не** отслеживает в реальном времени прогресс кухонных
действий, не рассчитывает гарантированное критическое расписание
и не запускает автоматические таймеры. Реализованы улучшенные правила
планирования на этапе генерации, проверка ссылок на таймеры и отображение
параллельных действий. Реальную согласованность сгенерированных рецептов
нужно проверять на примерах и при живом тесте ClaudeHub.
