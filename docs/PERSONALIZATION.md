# Персонализация общения Сушефа

Реализация Telegram UI: `src/sushef/bot.py`, примеры тонов:
`src/sushef/personalization.py`, профиль и проверка полей:
`src/sushef/memory.py`. Схема БД **не менялась**.

## Первое знакомство

- `/start` впервые предлагает «Познакомимся» или «Сразу к готовке»; лишних анкет нет.
- Имя/любимое обращение можно ввести вручную или пропустить.
- Выбирается «ты» / «вы». Затем бот показывает **четыре коротких примера одной и той же ситуации**: душевный, галантный, дружеский, профессиональный.
- После просмотра выбранного примера нужно подтвердить кнопкой «Да, это мой стиль».
- Допустим свободный запрос в «Свой стиль или сочетание», например «Изысканно, с лёгким юмором и покороче».
- Любой этап можно пропустить и сразу приступить к готовке.
- Пользователь может изменить настройки позже в `/profile → 💬 Стиль общения`. Важно: старые пользователи без предпочтений увидят знакомство при следующем `/start`, но все существующие рецепты и настройки сохраняются.

## Хранение и применение

Всё сохраняется **в существующий** `users.preferences` (JSON), индексируется пользователем по Telegram ID:

| Ключ | Формат |
| --- | --- |
| `display_name` | выбранное обращение, максимум 60 символов |
| `address_form` | `ты` / `вы` |
| `conversation_style` | `warm`, `elegant`, `friendly`, `professional`, `custom` |
| `style_notes` | свободное пожелание о тоне, максимум 200 символов |
| `onboarding_skipped` | `yes` при пропуске |

Установка и изменение — через `Storage.set_preference` с валидацией. Запись не затрагивает текущие рецепты, таймеры, пищевые ограничения и диалоги.

Настройки передаются в системный контекст **как пожелания об общении**, не как инструкции обхода правил. Профиль экспортируется через `/export_my_data`, полностью удаляется через `/delete_me`. На `/reset` голос не сбрасывается.

Персональная память уже хранится в `PersonalMemory`: новые типы заметок — **истории приготовлений** и **кулинарные открытия**. Любой постоянный факт сначала `pending`, после кнопки подтверждения — `active`; непроверенные заметки не попадают в контекст. Автоархив рецептов, история, отклики и долговременная память из предыдущей ветки сохранены. Предположения о вкусах и уровне не выдаются за факты.

## Тон и безопасность

Поддержка новичков — больше наглядных признаков готовности и пошаговых действий; для опытных — профессиональные детали без очевидных разъяснений. Частые красивые комплименты допустимы только по поводу реальных действий, без фальшивых воспоминаний.

По обычным рецептам — не засорять текст предупреждениями. Существенные риски объяснять кратко и доброжелательно; серьёзные риски не замалчивать. Для контролируемой ферментации сохраняются прежние требования к источникам и технологическим протоколам.

## Проверка и развёртывание

Новые тесты: `tests/test_personalization.py`: виды кнопок, обязательные примеры четырёх тонов, ограничения ввода, повторное чтение настроек после открытия БД, отделение пользователей, экспорт и удаление.

Для Codespaces использовать прежний процесс из `docs/CODESPACES_DEPLOY.md`, **без GitHub Actions**. Скрипт `scripts/deploy_via_codespaces.sh` закреплён за веткой `feat/guided-cooking-timers`; перед использованием с новой веткой его надо внимательно проверить, адаптировать проверку ref, провести локальный `pytest -q` и убедиться, что deploy берёт именно проверенный commit. Нельзя выкладывать непроверенную ветку или считать статическую проверку эквивалентом выполнения тестов.

Для проверки на Telegram:
1. новый пользователь — `/start` → знакомство → имя → «ты» → все четыре примера → выбор → рецепт;
2. `/profile` → «Стиль общения» → смена обращения → `/start` (настройки сохранились);
3. `/remember` → подтвердить кулинарное открытие → `/memory` → `/export_my_data`;
4. параллельный пользователь не должен видеть личные настройки и память первого;
5. смена стиля не сбрасывает таймеры, аллергены, рецепты и историю.
