# Развёртывание без GitHub Actions

### О хранении секретов

**GitHub Actions Secrets — не серверные переменные окружения.** Если токен Telegram и API-ключ ClaudeHub добавлены в Settings → Secrets and variables → Actions, это не даёт серверу или нашему чату доступа к их значениям. Секреты доступны только явно настроенным workflow; GitHub не позволяет прочитать их значения обратно.

Для постоянного запуска создайте на сервере закрытый от других пользователей файл `.env` с `TELEGRAM_BOT_TOKEN` и `CLAUDEHUB_API_KEY`. Никогда не коммитьте `.env` и не отправляйте содержимое в чат. Названия секретов должны точно совпадать с названиями в [.env.example](../.env.example). Если секреты созданы для Codespaces, проверьте их доступность отдельно: область Codespaces отличается от Actions.

### Локальная разработка / первый пробный запуск: один контейнер + SQLite

В директории клонированного проекта на сервере с Docker/Compose:

```bash
cp .env.example .env
chmod 600 .env
# Впишите реальные значения ключей в .env на сервере (не в Git).
docker compose -f compose.sqlite.yaml up -d --build
docker compose -f compose.sqlite.yaml ps
```

SQLite хранится в постоянном Docker volume `sushef-data`. Один экземпляр Telegram long polling: не запускайте второго экземпляра с тем же токеном. Обновление: `docker compose -f compose.sqlite.yaml up -d --build`.

### Рекомендованный для нового продакшна запуск с PostgreSQL

Используйте `compose.yaml` и укажите в `.env` дополнительную переменную `POSTGRES_PASSWORD` — сильный случайный пароль без URL-спецсимволов. Команда: `docker compose up -d --build`.

### Проверка без раскрытия секретов

1. Проверьте `docker compose -f compose.sqlite.yaml ps` — состояние контейнера.
2. В личном чате Telegram: `/start` → «Что приготовить?» → список продуктов.
3. Проверьте рецепт, пошаговую готовку, избранное, профиль и очистку `/reset`.
4. После смены аллергенов убедитесь, что старый рецепт сброшен; проверьте `/privacy` и `/delete_me` на тестовом аккаунте.
5. Smoke-test API делает настоящий запрос и расходует токены. Статус Docker сам по себе не доказывает успешную работу ClaudeHub.

**Политика расходов:** GitHub Actions не создаём и не запускаем ради проверки. Деплой исключительно через локальный доступ к серверу. Существующие сервисы на сервере не трогать.

Источники: [GitHub Secrets](https://docs.github.com/en/actions/concepts/security/secrets), [Docker Compose environment](https://docs.docker.com/compose/how-tos/environment-variables/set-environment-variables/).


## Настройки расширенной версии

После тестирования конкретного vision-маршрута можно включить `VISION_ENABLED=true` и задать `MAX_PHOTO_BYTES` (по умолчанию 4 МБ). Пока не проверена поддержка изображения в ClaudeHub, оставьте `VISION_ENABLED=false`.

Миграции Alembic включены и выполняются Docker-контейнером **до** запуска polling-бота. Новые таблицы для кулинарной памяти и автоархива создаются без удаления старых данных; отсутствующие столбцы ID/версии ферментации добавляются. **Перед обновлением существующей базы нужен резервный снимок** и тест миграции на копии. Подробный регламент: [MEMORY_AND_DATA.md](MEMORY_AND_DATA.md).

**Нельзя** просто изменить DATABASE_URL с SQLite на PostgreSQL и ожидать переноса данных — автоматическая миграция содержимого между этими движками пока не реализована.

Бэкап PostgreSQL вручную, без Actions: `bash scripts/backup_postgres.sh /secure/backups/sushef`. Проверяйте восстановление отдельно; старые бэкапы могут сохранять удалённые из рабочей базы персональные данные. Договорённость о сроках хранения и шифровании должна быть определена до запуска.


## Запуск с таймерами

В ветке `feat/guided-cooking-timers` необходима **миграция `0002_timers`**. Docker запускает Alembic до старта бота. При ручном запуске команду `PYTHONPATH=src alembic upgrade head` нужно выполнить в окружении с `DATABASE_URL` **до** `PYTHONPATH=src python -m sushef`. Бот проверяет схему и намеренно завершает старт при пропущенной миграции. Для существующей базы — только после резервного копирования.

Длительность таймеров не зависит от того, открыт ли чат Telegram; но отправка требует работающего процесса Сушефа и доступа к Telegram API. При выключенном сервере напоминание будет отложено до восстановления. Worker начинает проверку очереди при старте бота и проверяет её примерно каждые 5 секунд; один polling-экземпляр, без отдельного scheduler/Actions.

Проверка после тестовой миграции: `/start` → новый рецепт → «Готовим пошагово» → таймер 1 мин → следующий шаг → `/timers` → уведомление → повторный вход с того же шага. Отдельно проверить отмену /reset, смену аллергенов и перезапуск сервера. Подробнее: [COOKING_TIMERS.md](COOKING_TIMERS.md).


## Codespaces: запуск через задачу VS Code

Для сервера `155.212.162.47` добавлен скрипт `scripts/deploy_via_codespaces.sh`, который запускается из меню **Terminal → Run Task → «Сушеф: Тесты + деплой на сервер 155»** в Codespace ветки `feat/guided-cooking-timers`. Перед обновлением выполняются Python-тесты и при наличии существующей БД — бэкап. После старта контейнера делаются Telegram getMe + один короткий ClaudeHub smoke-test. Секреты находятся в доступе Codespaces, а не только Actions. Подробности: [CODESPACES_DEPLOY.md](CODESPACES_DEPLOY.md).
