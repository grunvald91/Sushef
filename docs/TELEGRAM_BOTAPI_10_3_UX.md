# Сушеф — Telegram Bot API 10.3: новые возможности и границы

Проверено по https://core.telegram.org/bots/api-changelog и https://core.telegram.org/bots/api 10 октября 2026 г. Последняя документированная версия — Bot API 10.3 (24 августа 2026 г.).

## В исходниках реализовано

1. Rich Messages: карточки рецептов с заголовками, перечнями продуктов, шагами и раскрывающимися подробностями о причинах, признаках и исправлениях. Данные из модели экранируются. При подтверждённом Telegram BadRequest используется обычный HTML, но неопределённые сетевые ошибки автоматически не повторяются.
2. Цветовые стили кнопок primary/success/danger: для основных, позитивных и потенциально разрушительных операций соответственно.
3. DisabledButton (10.3) — неактивная кнопка «назад» на первом шаге, с защитой от старых активных сообщений.
4. force_reply (10.3) для ввода собственного стиля с сохранёнными кнопками выбора.
5. CopyTextButton — копирование списка продуктов длиной не более 256 символов; непомещающийся список не обрезается.
6. sendMessageDraft — недолговременный статус подготовки ответа ClaudeHub, НЕ потоковая передача сгенерированных токенов; обычное «печатает...» остаётся запасным вариантом.
7. Telegram-команды с русскими описаниями, компактное главное меню, разделы «Моя кухня», «Все возможности». Кнопка Mini App, если задана владельцем в BotFather, не перезаписывается.
8. Повышенная почтительность и изысканная манера: частые разнообразные комплименты к фактическим выборам, вкусам, любознательности и идеям; подтверждённые индивидуальные предпочтения используются без выдуманной истории.

## Что не следует включать без подготовки

Mini App — отдельный полноценный веб-интерфейс, ему нужны HTTPS-сайт, проверка Telegram.WebApp.initData на сервере, серверное разграничение доступа к рецептам и памяти, тесты на мобильном Telegram и адаптивность через safe area. Текущий Rich Message HTML не исполняет произвольный JavaScript в сообщении.
Ephemeral group messages, управление другими ботами, бизнес-режим, live photos, Communities, гостевой режим и другие методы API 10.x не имеют отношения к личной готовке либо требуют отдельного сценария и разрешений. Custom Emoji требуют права владельца/платформы, неподтверждённые emoji IDs не вставляются.
Настоящее потоковое воспроизведение вывода модели требует подтвердить поддержку ClaudeHub streaming и отдельную работу со стоп-сигналами. Сейчас используется только недолговременный черновик-статус.

## Контроль выпуска

Нужен aiogram>=3.31,<4. Два выключателя Settings: telegram_rich_recipe_cards и telegram_draft_preview (по умолчанию включены).
Новые офлайн-тесты tests/test_telegram_modern.py и обновлённые тесты основного меню.
Исходники находятся в ветке feat/telegram-botapi-10-3-chef-ux-20261010. Полный pytest и production smoke из данного подключения НЕ выполнялись. Нужны бэкап PostgreSQL, тест миграции Alembic 0005 на копии, испытание восстановления, подтверждение живого Telegram/ClaudeHub и проверка клиентов без новых Rich Messages. GitHub Actions не запускать.
