# 👨‍🍳 Пошаговое приготовление и устойчивые таймеры

**Ветка:** `feat/guided-cooking-timers` поверх `feat/long-term-memory`.

## Что делает пользователь

1. Получает структурированный рецепт. Если модель предлагает выдержку по времени, она попадает в необязательное поле `step_timers` — только **подсказка**.
2. Нажимает «👨‍🍳 Готовим пошагово», читает **один шаг за раз**.
3. На шаге выбирает «⏱ Поставить таймер»: рекомендуемая длительность (при наличии), кнопки 1/5/10/15/30 минут или своё число 1–240 минут.
4. Таймер **не стартует сам**: требуется явное действие пользователя. Каждый таймер запоминает блюдо, номер шага, длительность и назначение.
5. Можно перейти к следующему или предыдущему шагу **без остановки таймера**. Максимум 5 одновременных таймеров на Telegram ID.
6. `/timers` или «🔔 Мои таймеры» показывает активные отсчёты и позволяет отменить каждый.
7. При срабатывании бот направляет обычное Telegram-сообщение в тот же личный чат. **Рецепт не перелистывается автоматически**: пользователь сам проверяет результат и нажимает «Следующий».
8. Повторное открытие режима «Готовим пошагово» на том же рецепте **возобновляет текущий шаг**, а не возвращает к первому.

### Когда таймеры отменяются

- Явная отмена конкретного таймера;
- `/reset` (диалог и активное приготовление);
- `/delete_me` (все данные пользователя, включая таймеры);
- смена текущего рецепта или активация другого рецепта из избранного/архива;
- изменение аллергенов или запрещённых продуктов.

Если пользователь проходит все шаги раньше срабатывания таймера, **активный отсчёт сохраняется**, чтобы важное напоминание не пропало. При этом бот не объявляет блюдо готовым, пока пользователь не проверит его.

## Хранение

Модель `CookingTimer` в таблице `cooking_timers`:

| Поле | Для чего |
|---|---|
| `user_id`, `chat_id` | Изоляция пользователя, личный чат Telegram |
| `recipe_title`, `step_index`, `label` | Какому блюду и шагу принадлежит уведомление |
| `minutes`, `due_at_ts` | Продолжительность и момент срабатывания в Unix UTC |
| `status` | `active`, `sending`, `delivered`, `cancelled`, `failed` |
| `lease_until_ts`, `retry_at_ts`, `attempts` | Устойчивость очереди к сбоям и повторным попыткам |

`0002_cooking_timers.py` — безопасная миграция Alembic. Для уже существующей базы перед обновлением обязательно делать резервную копию. Сама команда `python -m sushef` проверяет, что применена схема версии `0002_timers`, и отказывается работать, если миграцию забыли.

## Как приходят напоминания

- `src/sushef/timer_worker.py` — асинхронный цикл внутри **работающего экземпляра** бота, опрашивающий БД примерно каждые 5 секунд.
- `claim_due_timers` атомарно резервирует просроченный таймер через условный SQL UPDATE и устанавливает 120-секундную lease.
- `deliver_due_timers` повторно проверяет статус перед отправкой; отменённые/удалённые таймеры не должны рассылаться.
- После успешного Telegram API-запроса статус `delivered`. Если отправка не удалась — backoff и до 5 попыток, затем `failed` и серверная запись о проблеме.
- Если процесс остановлен в момент срабатывания, уведомление отправится **после его восстановления**, а не в отсутствие сервера. Это не системный будильник смартфона.
- В редком случае завершения процесса **после Telegram send, но до подтверждения в БД** повторная доставка возможна. Очередь обеспечивает *at-least-once*; абсолютное exactly-once с внешним Telegram API не гарантируется.
- В многопроцессной/многосерверной схеме потребуется отдельный воркер и полноценный distributed scheduling. На текущем этапе один aiogram polling-бот и отдельный PostgreSQL подходят.
- Расходы ClaudeHub: создание/отмена/уведомление таймера **не требуют LLM-запроса**. Рекомендации `step_timers` приходят в JSON обычного рецепта.

## Пищевая безопасность

- Отсчёт времени — **напоминание проверить** результат, а не доказательство пищевой безопасности.
- Недопустимо автоматически объявлять блюдо готовым только по таймеру; для птицы, мяса, рыбы и иных рискованных продуктов нужен надёжный контроль температуры и технологии.
- Не превращать свободно предложенный LLM таймер в проверенную технологию ферментации, кодзи, созревания мяса и прочих рискованных процессов. Эти процессы регулируются отдельной библиотекой протоколов.

## Тестирование и запуск без GitHub Actions

После `pip install -r requirements-dev.txt` и настройки путей:

```bash
export PYTHONPATH=src
python -m compileall -q src tests
pytest -q tests/test_timers.py tests/test_timer_storage.py tests/test_migrations.py
```

Перед запуском локального бота или контейнера `alembic upgrade head`. Dockerfile делает это автоматически до старта. Для existing PostgreSQL сначала `bash scripts/backup_postgres.sh /secure/backups/sushef` и желательно прогон миграции на тестовой копии.

Smoke-тест с отдельным тестовым Telegram ID: рецепт с 2–3 шагами → начать готовить → запустить минутный таймер → перейти к следующему шагу → вернуться → проверить, что первый таймер остался → получить сообщение после минуты → нажать «Следующий». Затем отдельно проверить перезапуск бота и отмену нескольких таймеров.

**Статус:** исходники и тесты добавлены, но живой бот и реальные уведомления Telegram ещё не проверены, деплоя пока нет.
